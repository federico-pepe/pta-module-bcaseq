# CLAUDE.md

BCA Sequencer is a Python 3 (stdlib only) process module for `push-tethered-app`. It is a MIDI step
sequencer with switchable pad Layouts. Built from `pta-module-gridseq`.

@~/.claude/push-family.md

## Files
- `run.py`: only file that touches stdin/stdout. Dispatch, LED diff plus 1 s full resend, save/load.
- `engine.py`: model, global rate, clock, triggers, `Friction` encoder helper. No I/O.
- `layouts.py`: pad mapping and pad colors per Layout. A Layout never changes sequencer behavior.
- `view.py`: screen ops, button colors, OSD popup. No state changes.
- `clockout.py`: thread that sends MIDI clock ticks in Lead mode. Reads `engine.lead` and the BPM only.
- `chords.py`: chord names from MIDI notes (`chord_name(notes, flats)`) and pitch class spelling. Pure. Minor is "min" because the screen font is upper case only. `pattern["flats"]` (Scale menu, encoder 6) picks sharps or flats everywhere.
- `colortable.py` (+ optional `colors.json`): dim pad shade and screen RGB per track color. Tune with the `colorlab-py` example module in push-tethered-app, not by hand.
- `palette.json`: all 128 hardware LED colors, generated by `scripts/gen_palette.py` from `ableton-push-hack/docs/push3-led-colors.md`. Do not edit. (gridseq's copy only has 90 named entries, so many indices show the wrong color.)
- `plans/`: design plans, dated. Never delete.

## Clock
- One shared clock: `engine._ticks` (24 ppqn). Do not keep a per-track step counter. Use `engine.step_at(track)` and `_advance`.

## Rules
- Update README.md and this file when a control or behavior changes.
- Screen text is ASCII only.
- Hardware change: deploy, wait for the user to confirm on the device, then commit.
- Do not commit or push unless asked. Land branches through a PR.
- Test: `python3 -m unittest discover -s tests`.
- Install: in `push-tethered-app`, `go run ./cmd/pushapp -install /path/to/this/repo`, then `-module bcaseq`.

## Notes
- A step holds `pitches`, a sorted unique list. There is no `step["pitch"]`. Use `engine.toggle_note` to add or remove a note and `engine.note_index(step)` for the selected note (`engine.sel_note`).
- `engine.rate_track` is the working track. The screen always shows 4 tracks (`layouts.screen_tracks`, page = `engine.track_page`). The pads show `layouts.pad_tracks`: the screen page in Layout 1, the pair or triple that holds the working track in Layouts 2 and 3. Layout 3's step grid is the working track.
- Tempo: `engine.bpm()` is the tempo measured from the external clock (one beat of ticks, `engine.ext_bpm`) while it runs, else `pattern["bpm"]`. Use it, not `pattern["bpm"]`, for timing. Roles: `engine.lead` (tempo encoder press, `toggle_lead`) False = follow an incoming clock (wheel does nothing), True = lead: `clockout.ClockOut` thread sends `send_clock` ticks from `pattern["bpm"]`, Start and Stop go out from `engine.start` and `engine.stop`, incoming clock is ignored. The thread writes to stdout, so `run.send` holds a lock.
- The MIDI channel of a track is a main-screen knob (first encoder of the track column, `engine.nudge_channel`). It is not an edit parameter: `PARAMS` has 7 entries.
- Layouts 2 and 3 use `engine.armed`, a set of note numbers. A pitch pad arms notes (hold a pad and press more to add). `engine.pitch_held` tracks the pads that are down: `run.handle_pad` calls `layouts.pad_release` on release. A step pad adds all armed notes with `toggle_notes(..., activate=True)`, or removes them when the step has all of them.
- `engine.pad_down` holds a record for each pad that is down. In Layouts 2 and 3 a plain step press and a disarm act in `layouts.pad_release`, and only if the press was shorter than `layouts.LONG_PRESS_S`. A longer press shows a highlight in `layouts.pad_colors` (pitch grids for a step, step grid for a pitch pad). While a step pad is held, a pitch press calls `toggle_note` for the same step index on the track of that pitch pad, and cancels the step press. Layout 1 taps act at once. Tests: use `tap(e, col, row)` for a step press in Layouts 2 and 3.

## Open questions for hardware
- Lead mode (tempo encoder press): does Live follow the clock, Start and Stop with Sync on and EXT? Is the clock from the thread steady enough? Does the Push report "Tempo encoder press"?
- Layout 3 colors: empty step (`STEP_DIM_WHITE` 119), unselected in-key pitch pad (`PITCH_DIM_WHITE` 118), selected pitch pad (`PITCH_WHITE` 120), root (dim track color, full when selected), long-press dim (`LONG_PRESS_DIM` 119 dark gray). Chord text on the main and edit screens.
- Empty step pad color (124, dgray) and playhead green (126) need a look on the device.
- Key and scale are global by default (`pattern["scope_global"]`). With Scope = Track each track has its own `root` and `scale`. Always use `engine.key_of(track)`. In Key is always global.
- Rate is per track. Scene buttons act on `engine.rate_track` (last touched track).
- Knobs are drawn with the host `arc` op (ring plus sweep). Check size and color on the device.
